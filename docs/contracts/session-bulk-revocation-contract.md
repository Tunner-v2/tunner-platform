# Private original-set session revocation

FRD17's Sign Out Other Sessions contract and catalog32's actor/version/policy invariants authorize this separate private `SESSION_REVOKE_OTHERS / USER_BFF` owner mapping. Bulk permission and assurance are explicitly selected by their trusted existing sources. A single-session grant is not inherited. No production capacity, assurance, lifetime, UI, HTTP, DeviceTrust or Product propagation is activated here.

Preparation accepts a current server-issued actor, original request/correlation and trusted versioned discovery source. One bounded server query discovers the complete original candidate set: other ACTIVE recorded sessions in the same Account, User scheme and origin. The query reads maximum+1; overflow rejects preparation rather than producing a partial manifest/page. All discovered IDs plus actor are locked canonically before acquiring the actor/Account/user locks. A discovered version change rejects preparation. Current effective expiry, stamp and method checks exclude candidates that already cannot authenticate; every eligible original target is retained. Foreign Accounts, origins, Admin sessions and the actor are never selected. A zero eligible set returns nonmutating absence, not an applied receipt or consumed proof.

The immutable defensive manifest copies and sorts exact target IDs/versions and binds actor/Account/origin, request/correlation, discovery time/capacity version and authentication/assurance versions. Its aggregate resource is the original request identity; it has no mutable aggregate row, so the existing zero expected-version marker is used only for that non-versioned manifest resource. Every target version remains included in its canonical context digest. It represents the complete eligible original discovery, not sessions subsequently created or all sessions at a future commit time. Caller-facing browser persistence/transport of this exact manifest remains a later separately allocated boundary.

One typed StepUp call prelocks all manifest targets plus actor, then reuses the existing proof validation and final actor/policy/currentness decision. A small set compositor reuses the qualified single-target validation, local End/outbox and causal receipt mechanics. It does not loop nested owner calls, transactions, proofs or provider effects. One stale/expired/ineligible target or final policy/discovery-version change rolls back the entire set, every staged outbox entry and proof consumption. The actor continues under ordinary current-session validation. The generic proof entry rejects this owner scope.

Success requires all exact target revoked versions/operation/correlation and cleared material, each reference-only target outbox event, plus the same immutable consumed proof binding the full manifest and its consumption outbox event. Partial target receipts or a consumed proof alone never establish aggregate success. Duplicate/lost-response handling reads this exact evidence and never executes again to discover an outcome. Result reads independently authorize the original current actor for the bulk operation; unavailable evidence returns unconfirmed, not a claim that the operation cannot still finish. Completed reads need not reactivate an old discovery capacity or assurance policy; current actor authorization remains mandatory.

The application tests reuse the qualified SessionListingPostgresFixture and existing Identity setup. They cover complete discovery/overflow/absence, defensive manifests, explicit permission/assurance, one-proof N-target effects, exact duplicates, full rollback, competing sets, final currentness, causal incompleteness and exclusion of later-created sessions. No new runner, schema, dependency, production defaults or integration execution is introduced by this contract.
