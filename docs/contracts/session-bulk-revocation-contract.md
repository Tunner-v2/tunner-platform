# Private original-set session revocation

FRD17's Sign Out Other Sessions contract and catalog32's actor/version/policy invariants authorize this separate private `SESSION_REVOKE_OTHERS / USER_BFF` owner mapping. Bulk permission and assurance are explicitly selected by their trusted existing sources. A single-session grant is not inherited. The optional private browser transport below requires explicit sources; no production capacity, assurance, lifetime, UI, DeviceTrust or Product propagation is activated here.

Preparation accepts a current server-issued actor, original request/correlation and trusted versioned discovery source. One bounded server query discovers the complete original candidate set: other ACTIVE recorded sessions in the same Account, User scheme and origin. The query reads maximum+1; overflow rejects preparation rather than producing a partial manifest/page. All discovered IDs plus actor are locked canonically before acquiring the actor/Account/user locks. A discovered version change rejects preparation. Current effective expiry, stamp and method checks exclude candidates that already cannot authenticate; every eligible original target is retained. Foreign Accounts, origins, Admin sessions and the actor are never selected. A zero eligible set returns nonmutating absence, not an applied receipt or consumed proof.

The immutable defensive manifest copies and sorts exact target IDs/versions and binds actor/Account/origin, request/correlation, discovery time/capacity version and authentication/assurance versions. Its aggregate resource is the original request identity; it has no mutable aggregate row, so the existing zero expected-version marker is used only for that non-versioned manifest resource. Every target version remains included in its canonical context digest. It represents the complete eligible original discovery, not sessions subsequently created or all sessions at a future commit time. Trusted-original restoration is internal and accepts only the complete authenticated protected envelope; HTTP commands never supply targets or versions. Exact-original pending validation reuses canonical locks, target eligibility, current bulk permission and final policy checks without rediscovery.

One typed StepUp call prelocks all manifest targets plus actor, then reuses the existing proof validation and final actor/policy/currentness decision. A small set compositor reuses the qualified single-target validation, local End/outbox and causal receipt mechanics. It does not loop nested owner calls, transactions, proofs or provider effects. One stale/expired/ineligible target or final policy/discovery-version change rolls back the entire set, every staged outbox entry and proof consumption. The actor continues under ordinary current-session validation. The generic proof entry rejects this owner scope.

Success requires all exact target revoked versions/operation/correlation and cleared material, each reference-only target outbox event, plus the same immutable consumed proof binding the full manifest and its consumption outbox event. Partial target receipts or a consumed proof alone never establish aggregate success. Duplicate/lost-response handling reads this exact evidence and never executes again to discover an outcome. Result reads independently authorize the original current actor for the bulk operation; unavailable evidence returns unconfirmed, not a claim that the operation cannot still finish. Completed reads need not reactivate an old discovery capacity or assurance policy; current actor authorization remains mandatory.

The application and browser tests reuse the qualified SessionListingPostgresFixture and existing Identity setup. They cover complete discovery/overflow/absence, defensive manifests, explicit permission/assurance, one-proof N-target effects, exact duplicates, full rollback, competing sets, final currentness, causal incompleteness and exclusion of later-created sessions. No new runner, schema, dependency or production defaults are introduced. Test source is not execution evidence; committed-source runtime qualification is recorded separately.

## Optional private browser transport

`AddTunnerSessionBulkRevocation` requires explicit discovery, transport, assurance, shared proof presentation, separate bulk publication and listing sources. Missing registration leaves existing listing/single/fallback behavior intact. Bulk publication is conditional and separate from the 74 listing and 18 single-revocation keys. It does not approve or activate a production visual.

`POST /account/sessions/bulk-revocation/preview` accepts exactly `{}` for an explicit fresh review and issues a new server-owned request identity. It accepts exactly `{requestId}` only to replay the matching protected original; a missing/invalid original or mismatched ID rejects the replay without discovery. Null, empty, malformed and duplicate request selectors are rejected. Fresh preview discovers the complete server-owned manifest before review and writes a purpose-protected HttpOnly Secure SameSite Strict original cookie in draft state. The safe projection contains request/correlation, exact target references/canonical version strings, state, immutable server `preparedAt` from the original manifest discovery instant, and fixed expiry. The timestamp is display-only and never authorizes execution or renews the original. Merely reviewing, reloading or opening generic step-up never selects or executes this draft. `POST .../cancel` removes only an unactivated draft. Activated or uncertain originals remain available for exact result checking and cannot be cancelled or silently overwritten by a new preview.

A presented invalid original cookie, or surviving authenticated BULK selection evidence without its original, denies fresh replacement even when that evidence has expired. Such evidence only denies replacement; expired selection never grants proof or execution. After total capability loss the server cannot recover the old manifest from client identity. Its old request ID remains unusable for preview; an explicit fresh `{}` request creates a different operation identity rather than claiming restoration or durable request deduplication. No lost-cookie retry silently rediscovers a prior request's membership.

`POST .../activate` accepts exactly `{requestId}`, revalidates the same manifest and selects it for the shared proof dialog without changing membership, versions or expiry. It never rediscovers targets. A changed target, assurance, discovery or transport version conflicts. A subsequently selected family prevents activation of an earlier draft. Duplicate activation and preview return original state without renewing cookies or reselecting old intent. Explicit single-session preparation remains its existing already-confirmed path.

The entire manifest is preserved in one protected original envelope; no target truncation or pagination is allowed. The explicit versioned transport budget bounds small JSON commands and actual UTF-8 bytes of each complete framework-serialized Set-Cookie header, including name, protected encoded value and attributes. Both original and selection header sizes are checked before issuance. The 4096-byte RFC6265 section 6.1 minimum supported capacity is a conservative technical ceiling, never a production default or inferred candidate-count allowance. Overflow fails before any cookie or proof is issued. Missing/evicted/tampered capabilities fail closed without resnapshotting.

A separate purpose-protected original-selection cookie binds the selected family/request/digest, actor/Account/origin, authentication version and fixed original interval. One router dispatches only the explicitly selected single or bulk family and preserves independent-owner fallback/completed-owner handoff. Unselected originals are available only through their explicit context/result endpoints. Selection can recover the intended owner after a shorter shared view expires; proof and all native continuations still require their exact valid shared view. No proof or view lifetime is extended. Original lifetime is also bounded by the effective assurance, discovery and transport intervals. Typed bulk dispatch runs before the generic proof transaction and additionally enforces the original interval and transport/authentication versions at the existing final assurance-policy decision.

`GET .../context` returns `DRAFT`, `PENDING`, exact causal `COMPLETED` or `CHANGED` with the unchanged original projection. `POST .../result` accepts exactly `{requestId}` and independently authorizes the current original actor for the bulk operation. Only every exact causal receipt returns `REVOKED` with all target references/revoked versions/times. Unconfirmed results retain the original; they do not establish that an in-flight operation cannot finish. Completed reads do not require reactivating prior discovery or assurance versions. Query selectors, client target lists, malformed/extra/duplicate JSON, wrong media/size, missing CSRF, foreign origin/actor and stale capabilities are rejected under the existing BFF guards.

The existing persistent isolated browser-test profile supplies only explicitly synthetic discovery/transport/assurance/publication sources. No production UI files or visual approval are included in this backend increment.
