# P2-013 private owned-session application read

Derived from FRD17 sections 8, 9, 13 and 15; catalog32 command/Identity/policy boundaries; ADR-0006 and the existing authentication-session contract. The application read, private HTTP transport and optional Sessions presentation introduce no revocation, device/trust authority or production composition.

`AuthenticationApplication.ListOwnedSessionsAsync` accepts an Identity-issued User caller and an explicit trusted positive read budget. There is no production default or browser-selected policy. `LIST_SESSIONS` is independently resolved through the existing Account access source; `SESSION_USE` alone does not authorize it. Existing caller session, method, contact, stamp, Account and current policy validation remains authoritative. Missing/stale/denied authority returns no listing or fails closed.

Rows are scoped to the real Account, User scheme and exact caller origin. The bounded query sorts by authenticated time and session ID, reads at most budget plus one and returns an honest `HasMore` and actor/Account/origin-bound internal next boundary. A changed actor cannot reuse that boundary. Continuation is a live keyset read, not a frozen inventory: subsequent changes and insertions may affect subsequent pages. The optional HTTP adapter described below protects that boundary and requires explicit approved runtime capacity; internal continuation fields must never be serialized directly.

Projection contains only a non-bearer session reference/version, current-session distinction, trusted timestamps, recorded/effective lifecycle state and evaluation time. It exposes no Account/contact identifiers, origin/client labels, authentication methods/assurance, digests, protected ticket/key, IP/location or invented device/trust evidence. Effective expiry and denial reuse the existing session policy/method/stamp predicates, including lazy credential revocation; they are observations, not new persisted transitions or future usability guarantees. Target rows are read without changing their activity, version, state or outbox. Ordinary current-actor validation may update its activity/version or persist its existing expiry/revocation behavior.

The read owns its clean Identity transaction, locks the current actor/Account through the existing primitive, and rechecks current policy/access/method validity after asynchronous work. It does not acquire cross-session mutation locks or execute side effects on listed sessions. Future revocation must independently reauthorize/reload the selected version; listing is not authorization to revoke. Product-local sessions and propagation remain separate.

Tests use existing xUnit/Testcontainers and shared Identity database provisioning. Their explicit disposable fixture uses a cached immutable PostgreSQL image, no pull, loopback-only dynamic port, safe logging, child-only integration opt-in and run labels for exact cleanup verification. Synthetic test budgets and policies are not approved production values. No acceptance or passing test execution is asserted by this contract.

## Optional private HTTP transport

Register an explicit `ISessionListingHttpBudgetSource` to activate only `POST /account/sessions/list` on the existing authenticated User mapping. Absent registration installs no route and changes no authentication response or host composition. Resolve the source in each request scope. `SessionListingHttpBudgetCatalog` reuses approved policy-version/effective-time resolution for scope `USER_BFF_SESSION_LISTING`; maximum rows and request bytes are explicit positive values, without production defaults.

Accept only a JSON object containing optional `continuation` (null for first page, otherwise a nonempty protected string). The shared bounded parser rejects unknown/duplicate fields, wrong types and malformed/excessive bodies. Reject all query parameters. Actor, Account, origin, keyset, policy and budget values are never request authority. Existing HTTPS/host/Origin/current User authentication and antiforgery middleware runs before the handler. Obtain current antiforgery through the existing authenticated session endpoint.

A dedicated Data Protection purpose protects the internal next boundary, original Account/actor session/origin, budget version and values, authentication-policy version, creation time and original expiry. Expiry uses the explicit AuthenticationPolicy browser-context lifetime, clipped to the budget interval; paging never renews it. Every page independently invokes the existing application authorization/currentness checks, then rechecks current budgets/authentication policy before returning. The token is a read continuation, never authentication, revocation authority or an operation-result proof; keep it out of URLs, logs and storage.

Serialize an explicit safe DTO only: sessions contain reference, invariant string version, current distinction, trusted timestamps and explicit ACTIVE/REVOKED/EXPIRED recorded/effective labels. Return hasMore and the opaque continuation; never serialize internal boundary Account/actor/origin. No device/trust/provider/Product state is inferred.

Use generic technical problems: malformed/query shape 400, content type 415, excessive body 413, invalid/foreign/expired continuation 404, changed budget/authentication version 409, unavailable required authority/protection 503, and invalid/list-denied actor 401 (the existing application read does not disclose which authorization predicate failed). Shared no-store/nosniff/no-referrer headers apply to success and errors. The POST itself introduces no public SDK or UI route, production policy, revocation, Product propagation or acceptance claim.

## Optional Sessions presentation and packaged screens

Only explicit registration of both `ISessionListingPresentationSource` and `ISessionListingHttpBudgetSource` maps `GET /account/sessions/options` and the Sessions screens. Budget-only registration retains the existing POST listing behavior without adding these presentation routes. Options requires the current authenticated User scheme, rejects query selectors, resolves current approved capacity/authentication policy and calls `RequirePublished(AuthenticationPolicy)`. It returns exactly `{locale, content}` using the shared RegistrationPublishedText provenance contract. All 74 agreed semantic `account.sessions.*`/brand keys must be present, PUBLISHED, nonempty and in the requested locale with variant/version/publication references. Missing, invalid, withdrawn or unavailable content fails closed; no production text or publication fallback is synthesized.

CSRF comes exclusively from the existing authenticated `/authentication/session` endpoint. The UI must not bootstrap it through anonymous `/authentication/options`. Published options or rendering a page is not authorization to list: each POST continues to perform the existing independent LIST_SESSIONS checks. The POST listing implementation and response remain unchanged by presentation registration.

The unchanged IdentityWebAssets mapper serves packaged `sessions.html` at `/account/sessions` and `/account/sessions/details`, guarded by the current authenticated User session and exact origin. Anonymous, expired or revoked entry redirects to `/login`. Missing packaged entry files install no screen route. The focused route-guard test requires the real built entry in test output and exercises actual redirect/HTML responses; it creates no fake HTML and cannot pass by skipping missing packaging. The independent frontend scope owns selection/history handling and applicable rendered/browser/URL/Figma evidence. No revocation, device trust, policy defaults or Product guarantee is added here.

The dedicated local SQL profile additionally requires an explicit run ID and expected engine identity. If no dedicated run ID is supplied, its SQL cases skip rather than fail unrelated generic integration runs; malformed supplied metadata fails closed. Actual qualification requires all expected SQL and contract cases executed with zero skips. This increment does not claim a wired CI transport/profile. In the installed Testcontainers4.15.0 Ryuk-disabled mode, object disposal stops the container; the fixture explicitly removes only its retained created container ID through the existing Docker client with volume removal, then verifies exact container and captured volume absence.
