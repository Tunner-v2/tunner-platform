# P2-002 — Adult eligibility and derived evidence

Authority: FRD 17 section 11, PDR-0007, privacy FRD 29, contract catalog 32 and architecture document 02. The Accounts module owns this business predicate; shared Platform primitives do not own age semantics.

The internal typed evaluator accepts a transient DateOnly DOB and trusted application-supplied active AgeAssurancePolicy version, opaque evidence reference and correlation ID. The injected server TimeProvider is read once per evaluation. UTC instant and evaluation date are captured together; the caller cannot supply an evaluation date through the method. Eligibility uses DOB.AddYears(18) <= evaluation_date, with no day-count approximation. .NET Gregorian year addition adjusts a February 29 anniversary to February 28 in a non-leap target year. An anniversary beyond the maximum representable year is later than every supported evaluation date, so the result remains ineligible without overflow. Future DOB input also fails the approved predicate.

Ineligible results carry AGE_INELIGIBLE. The immutable derived evidence carries eligibility status, evaluation instant/date, AgeAssurancePolicy family/version, evidence and correlation references. Raw DOB is absent from the result, diagnostics and serialization; the evaluator stores or logs no input. The existing DateOnly contract excludes impossible calendar dates before evaluation. Missing clock or provenance is an invalid internal invocation and cannot produce evidence.

This slice adds no host wiring, endpoint, Account/session/Product activation, database storage, provider or UX. The future registration application must resolve the effective approved policy version with existing P1 resolution primitives, supply trusted operation references and discard raw DOB after authoritative commit unless an approved processing/retention contract requires it. The evaluator does not assert that a caller-provided policy string is approved and introduces no new retention or jurisdiction rule.

The module is a small independent project at src/Modules/Accounts with no external packages or infrastructure references. Its xUnit project is included in Tunner.Platform.slnx, so existing platform CI restore/build/test includes it automatically. Tests cover ordinary and leap/century birthdays, calendar boundaries and representable limits, UTC rollover, one clock read, exact provenance, replay, restricted-DOB minimization, invalid invocation and architecture boundaries. Committed SHA and actual test results are recorded in governance/evidence/TUN-P2-002-VALIDATION.json.

Technical references checked 2026-10-16: [DateOnly.AddYears](https://learn.microsoft.com/en-us/dotnet/api/system.dateonly.addyears?view=net-10.0) and [Gregorian year adjustment](https://learn.microsoft.com/en-us/dotnet/api/system.datetime.addyears?view=net-10.0). These establish runtime mechanics; the business authority remains PDR-0007 and FRD 17.
