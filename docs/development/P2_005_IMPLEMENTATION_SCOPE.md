# P2-005 authentication implementation boundary

This scope implements FRD17 password authentication and server-managed User BFF sessions through the existing Identity/EF/Accounts/outbox/policy foundations. It introduces no Product membership, federation, recovery, assurance elevation, Admin login or cross-Product logout. Google/Microsoft are unavailable placeholders pending P2-010; GitHub is deferred by explicit Product direction.

Production numeric limits, assurance mappings, processing/retention and Account restriction decisions require effective trusted versioned providers. Missing providers fail unavailable. Synthetic fixtures and browser mode are isolated Development data, not production policy approval. Password sign-in verifies existing credentials, not new-password registration composition rules. CLOSED and unverified accounts cannot authenticate; RESTRICTED/CLOSING are evaluated by scoped current Account policy; age classification alone cannot deny a normal session (AMD-0007/PDR-0011).

One cohesive Identity DbContext/model owns sessions, authentication operation deduplication and abuse state. Server ticket storage persists encrypted tickets and hashed random lookup keys, binds User scheme/origin, rechecks Account/contact/security stamp/restriction and policy expiry on retrieval, and revokes idempotently. New authentication rotates the lookup key and revokes the prior browser session; sign-out cannot revive or extend a session. Password and raw bearer material never enter logs, audit payloads or browser storage/URLs. Post-commit audit events use the transactional outbox.

Reuse the framework cookie handler, CSRF/origin/cookie foundation and Data Protection. Owner activation extends named options without weakening the closed P1 foundation. A fresh credential-authentication request is anonymous at the cookie boundary and requires protected browser context plus anonymous CSRF; it binds the prior opaque cookie fingerprint/session and forces StoreAsync instead of the framework existing-key RenewAsync path. Race/replay/stale bootstrap tests must demonstrate rotation and fail-closed behavior. The HTTP boundary strictly validates payload shape/size, trusted policy, identifiers and idempotency before mutation.

Frontend reuses @tunner/ui typed schemas, field errors, form summary, focus/correction and pending guards. Canonical /login and guarded /signed-in support reload/history/direct entry without secrets. Shared slate/error/interaction patterns, exact source assets and approved responsive reuse follow the consent receipt; no independent redesign. Existing registration routes, forms and content remain regression-covered. Shared source overlaps require fresh owner validation and historical evidence retention. Inventory changes must preserve closed work-item RV lineage.
