## Theme structure

A single versioned JSON source owns three distinct layers: primitive values, semantic roles per application/mode, and component aliases. A deterministic compiler emits scoped CSS custom properties, typed supported modes/surfaces and the Tailwind v4 inline theme bridge used by TailAdmin. Checked-in generated outputs must match the source; unresolved aliases, cycles, incomplete profiles and stale output fail validation. Production component CSS consumes named aliases and contains no per-screen palette/spacing overrides or inline styling escape hatch.

User light preserves Geist, indigo primary actions, slate text and 44px controls. Admin light preserves Inter, black primary actions, neutral text, 40px primary actions and 42px fields. Both profiles share the approved spacing rhythm and mechanical component implementation while retaining their Figma-specific typography, radii and metrics. Plain Tunner branding has no added icon. Self-hosted Inter/Geist font dependencies avoid remote font requests in the rendered foundation.

ThemeProvider scopes application and mode on its own DOM boundary. It never edits document/root classes, reads persisted browser state or derives an unapproved dark/system palette. Nested User/Admin providers remain isolated. Light is the only currently supported mode; another mode requires a complete approved semantic profile, regeneration and tests. Runtime invalid surfaces/modes fail explicitly instead of silently substituting another application profile.

The reusable primary Button and labelled TextField follow TailAdmin's native-button, disabled-state and controlled-input composition while adapting it to canonical Figma tokens. Native button type defaults to button; explicit submit is owner-selected. Owner callbacks/disabled/value/read-only state remain authoritative inputs. Labels, help and errors use versioned content keys rather than copy embedded in reusable components. No sign-in, provider setup, permission, validation rule, persistence or BFF/auth behavior is implemented by the controls.

## Content boundary

ContentProvider is a presentation contract over owner-supplied published content snapshots: semantic key, variant/version/publication references, locale, published state and plain text. Safe resolution context includes the selected surface plus explicit locale/audience. It does not implement a CMS, draft/publication workflow or browser authorization. Optional help/error slots are absent unless supplied. Backend content/publication and disclosure authority remain with their owners. The isolated developer fixture uses explicitly labelled development publication fixtures to test rendering and refresh; it is not a Product application or live content service.
