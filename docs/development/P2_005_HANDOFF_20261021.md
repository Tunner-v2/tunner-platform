## Architecture and implemented changes

- AuthenticationApplication/Contracts/Rows/Endpoints/Presentation and the P2PasswordSessions migration implement policy-sourced password authentication, HMAC-scoped abuse counters, PostgreSQL lifecycle locks/retries, absolute/idle/remember expiry, revocation, outbox and trusted maintenance. Policies and access decisions fail closed without effective trusted providers.
- New TunnerAuthenticatedUserBffHost composes the existing isolated User BFF foundation. Framework ticket protection and server-side ticket storage are retained; cookie material is not returned as browser JSON. A fresh 256-bit lookup key is issued on credential authentication, including route aliases. User/Admin cookie separation, origin and CSRF checks remain independent.
- Trusted current Account/security-stamp/contact/access decisions are checked at authentication and session use. An under-18 Account is not denied a normal session merely because of age. Restriction/closing operation limits, pending/unverified and closed states remain authoritative.
- Independent backend strict JSON/domain validation rejects browser-validation bypass. No password-registration rules are copied into Login. HTTP endpoints are GET /authentication/options, POST /authentication/sign-in, GET /authentication/session and POST /authentication/sign-out.
- authentication.tsx/.css/.routes.ts/.validation.ts reuse the existing theme, field/error components, Zod/useTunnerForm and navigation primitives. They supply /login and guarded /signed-in, safe value preservation, password clearing/reveal, first-error focus, pending protection and truthful server errors.
- IdentityEmail and IdentityWebAssets consolidate shared mechanics. HTML entry points are governed separately from static assets, so nested asset aliases cannot bypass screen route guards. Registration business semantics remain unchanged.
- Vite multipage composition, all-three-suite browser command and distinct Playwright output directories preserve all 54 dev-browser tests/screenshots. No package or independent visual system was introduced.
- The isolated starter now exposes password sign-in/sign-out through Development-only synthetic providers. Production provider/content/legal configuration and later federation/recovery/assurance features remain outside this implementation.
