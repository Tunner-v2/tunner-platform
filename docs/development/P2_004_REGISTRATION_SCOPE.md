# P2-004 registration and normal Personal Information scope

Current authority: verified PDR-0011 / AMD-0007 and current FRD17/18/21/29/31/32/34. The prior PDR-0007 implementation/receipts remain historical in Git and preserved validation history. P2-004 was VALIDATION, not CLOSED; this is a correction within its active lifecycle, with no RV and no new Product decision.

Initial registration collects email, password, confirmation and effective terms/privacy acknowledgment. It contains no DOB, age checkbox, guardian or age-band claim. Contact proof binds a bounded normal Personal Information form to the same Account and browser operation. The form uses approved full/display-name controls, verified email and required DOB; no DOB-only stage remains. Successful proof alone does not activate the Account. Server calendar evaluation, current jurisdiction/consent policy and trusted consent evidence determine completion. Under18 alone never denies Account activation, auth/session eligibility or ordinary Product relationship.

Identity preserves existing credential/proof, idempotency, concurrency, contact uniqueness, abuse and outbox controls. Account-owned protected profile storage is shared with later authenticated owner adapters. Raw DOB is not duplicated in registration or event/history/response material. No browser claim can authorize consent, jurisdiction, BillingAuthority or commercial eligibility.

P2-002 owns the shared age/consent capability evaluator; P2-003 owns the reusable persistence foundation; P2-004 owns this onboarding application and BFF/UI. Billing/Subscription implementation is absent. Only the existing future-plane boundary is implemented: under18 cannot independently resolve payer/payment-method/paid-term capability, while authorized guardian/adult/organization/school sponsorship uses existing BillingAccount/BillingAuthority contracts. This does not implement a new payment plane or authorize money movement.

Required trusted providers include current registration policy, jurisdiction-scoped age/consent policy, approved processing/retention, trusted consent evidence, password blocklist, notification boundary, network secret, Data Protection custody and published content. No production legal/security threshold, jurisdiction, retention duration or content publication is supplied by a fixture. P2-005 owns sign-in/session; P2-014 owns Product authorization; P2-016 owns production delivery/consent integration and maintenance scheduling.

Validation requires committed-source PostgreSQL/HTTPS, migration/history, calendar/policy, privacy/security, architecture and accessible browser checks, followed by truthful engineering role reviews. Product acceptance, protected-main integration and production release remain separate.
